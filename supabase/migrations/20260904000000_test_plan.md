## SETUP CẤU HÌNH PHIÊN LÀM VIỆC (SESSIONS)

Để test chính xác các rào cản phân quyền, DBA cần chuẩn bị 2 loại Session trong SQL Editor:

### Session A: Human Approver (User Session)
- Đăng nhập bằng tài khoản có role `department_owner` trong **Test Org A** (`aaaaaaaa-0000-0000-0000-000000000001`).
- Trong session này, `auth.uid()` trả về UUID của User thật.

### Session B: Webhook Engine (System Service Role)
- Thiết lập role hệ thống bằng câu lệnh:
  ```sql
  SET LOCAL request.jwt.claim.role = 'service_role';
  SET LOCAL app.verified_webhook_callback = 'true';
  ```
- Trong session này, `auth.uid()` có thể là NULL hoặc System UUID, nhưng `auth.role()` là `service_role`.

## TEST AUDIT IDEMPOTENCY (Bọc PL/pgSQL DO Block hợp lệ)

### T12: PASS — Test Idempotency Retry bằng PL/pgSQL Block & Kiểm tra trạng thái Document
> **Lưu ý Vận hành API/N8N:** Ở tầng Application (Next.js API route), khi nhận `unique_violation` từ DB do retry callback gửi trùng `correlation_id`, API sẽ bắt ngoại lệ này và trả về HTTP 200/204 Idempotent Success cho N8N mà không gây ra lỗi 500.

```sql
DO $$
DECLARE
  v_count INT;
  v_doc_status VARCHAR;
BEGIN
  -- 1. Giả lập Session B (Webhook Service Role)
  PERFORM set_config('request.jwt.claim.role', 'service_role', true);
  PERFORM set_config('app.verified_webhook_callback', 'true', true);
  PERFORM set_config('app.correlation_id', 'test-corr-t12-idempotency', true);
  PERFORM set_config('app.ingestion_run_id', 'cccccccc-0000-0000-0000-000000000099', true);

  -- 2. Đưa doc về trạng thái hợp lệ
  UPDATE public.crm_knowledge_documents
  SET ingestion_status = 'PROCESSING'
  WHERE id = 'bbbbbbbb-0000-0000-0000-000000000001';

  -- 3. Callback lần 1: PROCESSING -> FAILED (Tạo audit log dòng 1)
  UPDATE public.crm_knowledge_documents
  SET ingestion_status = 'FAILED'
  WHERE id = 'bbbbbbbb-0000-0000-0000-000000000001';

  -- 4. Retry callback cùng correlation_id:
  UPDATE public.crm_knowledge_documents
  SET ingestion_status = 'PROCESSING'
  WHERE id = 'bbbbbbbb-0000-0000-0000-000000000001';

  BEGIN
    -- Lần 2 này sẽ bị đụng độ Unique Index: (document_id, action='INGESTION_FAILED', correlation_id)
    UPDATE public.crm_knowledge_documents
    SET ingestion_status = 'FAILED'
    WHERE id = 'bbbbbbbb-0000-0000-0000-000000000001';
    
    RAISE NOTICE 'T12 WARNING: Idempotency index chưa chặn được dòng trùng!';
  EXCEPTION WHEN unique_violation THEN
    RAISE NOTICE 'T12 PASS: unique_violation được bắt thành công — Audit Log chống trùng!';
  END;

  -- 5. Đếm số dòng log INGESTION_FAILED với correlation_id này
  SELECT COUNT(*) INTO v_count
  FROM public.crm_knowledge_audit_logs
  WHERE document_id = 'bbbbbbbb-0000-0000-0000-000000000001'
    AND action = 'INGESTION_FAILED'
    AND correlation_id = 'test-corr-t12-idempotency';

  -- 6. XÁC NHẬN TRẠNG THÁI DOCUMENT VẪN HỢP LỆ (Không bị hư hại sau Exception)
  SELECT ingestion_status INTO v_doc_status
  FROM public.crm_knowledge_documents
  WHERE id = 'bbbbbbbb-0000-0000-0000-000000000001';

  IF v_count = 1 AND v_doc_status = 'PROCESSING' THEN
    RAISE NOTICE 'T12 RESULT: PASS (Audit count = 1, Document State = PROCESSING safe).';
  ELSE
    RAISE EXCEPTION 'T12 RESULT: FAIL (Audit count=%, Doc Status=%)', v_count, v_doc_status;
  END IF;
END $$;
```

## KẾ HOẠCH ROLLBACK (Forward-Fix An Toàn — Không Xóa Dữ Liệu)

> **Nguyên tắc an toàn Production:**
> 1. KHÔNG Drop bảng Audit (`crm_knowledge_audit_logs`).
> 2. KHÔNG Drop cột dữ liệu Metadata để tránh Data Loss.
> 3. Tắt tính năng bằng cách vô hiệu hóa Trigger và khoanh vùng RPC.

```sql
-- Bước 1: Vô hiệu hóa Trigger chuyển trạng thái và Audit
DROP TRIGGER IF EXISTS trg_crm_knowledge_state_machine ON public.crm_knowledge_documents;
DROP TRIGGER IF EXISTS trg_crm_knowledge_audit_insert ON public.crm_knowledge_documents;

-- Bước 2: Khôi phục RPC về phiên bản safe-fallback (Giữ nguyên Tenant Guard)
CREATE OR REPLACE FUNCTION public.match_documents(
  query_embedding vector,
  match_count int DEFAULT null,
  filter jsonb DEFAULT '{}'
) RETURNS TABLE (id uuid, content text, metadata jsonb, embedding jsonb, similarity float)
LANGUAGE plpgsql SECURITY INVOKER AS $$
#variable_conflict use_column
DECLARE v_org_id UUID;
BEGIN
  IF filter ? 'organization_id' THEN
    v_org_id := (filter->>'organization_id')::UUID;
  ELSE
    RAISE EXCEPTION 'TENANT_ISOLATION_VIOLATION: organization_id is mandatory.';
  END IF;

  RETURN QUERY
  SELECT c.id, c.content, c.metadata, (c.embedding::text)::jsonb,
         1 - (c.embedding <=> query_embedding) AS similarity
  FROM public.crm_knowledge_chunks c
  WHERE c.organization_id = v_org_id
    AND c.metadata @> (filter - 'organization_id')
  ORDER BY c.embedding <=> query_embedding
  LIMIT GREATEST(1, LEAST(COALESCE(match_count, 10), 100));
END;
$$;

-- Bước 3: Đảm bảo phân quyền RPC an toàn (Tuyệt đối không cấp lại PUBLIC)
REVOKE EXECUTE ON FUNCTION public.match_documents(vector, int, jsonb) FROM PUBLIC, anon, authenticated;
GRANT EXECUTE ON FUNCTION public.match_documents(vector, int, jsonb) TO service_role;

-- Ghi chú: Bảng crm_knowledge_audit_logs và các cột metadata trên crm_knowledge_documents 
-- ĐƯỢC GIỮ NGUYÊN để bảo toàn nhật ký hệ thống và tránh làm hỏng dữ liệu đã có.
```
